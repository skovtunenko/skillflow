A flow file (<skill>.kdl) describes one skill's workflow so that a person can review it in minutes. Its nodes are the skeleton: phases, steps, decisions, who acts, data, invariants and exits. Its quoted strings are prose: the intent of each node.

1 · Syntax: KDL 2.0.0

A flow file is a KDL 2.0.0 document, not KDL v1, YAML or JSON.

Node

A name, arguments, key=value properties, then an optional { … } block of children.

step draft by=llm "Write the draft." { output draft "the first draft" }

End of a node

A newline, ; or the parent's } ends a node. A \ at the end of a line continues it.

phase p { step a by=llm; step b by=code }

Bare words and keywords

A word without spaces or (){}[]/\"#;= is a string. It cannot start with a digit. The keywords are #true, #false and #null; a bare true, false, null, inf or nan is an error.

output draft         // ok
output 2nd-draft     // error: starts with a digit

Quoted and raw strings

"…" holds text with spaces. Its escapes are \n \t \\ \" \s and \u{…}; any other \x is an error. A raw string has no escapes.

#"text with "quotes""#

Multi-line strings

Open with """ and a line break. Close with """ on its own line; its indent is removed from every line. """text""" on one line is an error. The page shows lists, `code`, **bold** and *italic* in it.

step draft by=llm """
    Group the changes **by type**:
    - features
      - new commands
    - fixes
    """

Comments

// runs to the end of the line. /* … */ sits inline. /- before a node comments out the whole node.

// a comment
/- step old by=llm

2 · Nodes

A flow file has only these nodes. A node in the wrong place is an error. Names of phases, steps and decisions are bare words, unique in the file. ref="label" links a node to the part of the skill that has that label.

skillflow

The first line

The format version, exactly 1.0. Reverse and sync add the stamps skill-version and skillflow-version. skill="path" names the target skill folder.

skillflow 1.0 skill-version="0.2"

context

Right after skillflow 1.0, optional

Facts about the whole skill: its inputs, outputs and invariants.

context "Drafts release notes." {
    input tag "the git tag to describe"
}

input

In context

What the user gives at the start, with a description.

input tag "the git tag to describe"

output

In context

What the skill produces, with a description. A named output must be produced on every path that reaches the end of the flow.

output "a new section in CHANGELOG.md"
output notes "the release notes"

invariant

In context

A rule that holds during the whole flow. Optional by says who keeps it: code is a script that fails or blocks, human a person at a gate or in a step of their own, llm the model's instructions alone.

invariant by=human "nothing is published without approval"

phase

Top level, phase, when

A group of steps.

phase write "Draft and approve." {
    step draft by=llm
}

step

Top level, phase, when, catch

One action. by is required: llm the model, code a script or fixed command, human the user. file= names the script of a code step; skill= names a skill the step loads.

step collect by=code file="scripts/collect.sh"
step draft by=llm "Group the changes by type."

decide

Top level, phase, when, catch

A fork of the path: a name, a question and by. At least one when holds a node or an end. With one when, the other outcome is implied and continues below.

decide mode "Which mode?" by=llm {
    when draft "the draft continues below"
    when publish { end "nothing to draft" }
}

gate

Top level, phase, when, catch

An approval by the user; no by. Two outcomes are implied: approved continues, revise redoes the work before the gate and asks again. A when adds an outcome or overrides an implied one.

gate approved "Did the user approve the draft?" {
    when rejected { end "stopped without approval" }
}

when

In decide, gate

One outcome, with prose or a block. After it the flow continues below the decide or gate, unless it reaches end.

when yes { step publish by=code }
when no "The draft stays local."

catch

In step, at most one

What happens when the step fails. Unless it reaches end, the flow goes on after the step. An output inside names data that the recovery restores.

step publish by=code {
    catch "Show the error." { end "nothing is published" }
}

end

Top level, phase, when, catch

The flow stops here. A node after it in the same block is an error.

end "the tag does not exist"

tools

In step, decide, gate

Tools the node uses: MCP, CLI, web and agent tools, such as a question tool. A name may carry its kind: (agent) a subagent, (mcp) a tool of an MCP server.

tools (agent)reviewer (mcp)jira gh

input output in a node

In step, decide, gate; output also in when and catch

output is data the node produces. input is material the skill asks the user for at that node.

output changes "the commits since the last tag"
input notes "the user's own notes on the release"

// ?

On its own line above a node

An unclear place in the skill. The page shows it as ❓ on that card.

// ? how many revision rounds? (SKILL.md:24)

3 · Example

A complete flow for an imagined skill release-notes: it drafts release notes for a git tag and adds them to CHANGELOG.md. It uses every node, property, executor and tool kind. Pick a point, or point at a line or a card: the other side shows its match.

by=code runs a script: collect-changes and publish. by=llm is the model: draft. by=human is work the user does alone: announce.

changes, size, highlights and draft each have one line with a description. highlights is an input: the step asks the user for it.

decide size forks the path. when major holds a step; when regular says in prose why nothing happens. Then both go on to draft.

gh is a CLI and has no kind. (agent)editor is a subagent, and (mcp)jira is a tool of an MCP server.

The catch of collect-changes ends the flow at once. The one of publish reports the error in a step of its own, then ends the flow. The one of announce is one line of prose, and the flow goes on.

The revision loop is in the prose of draft. A flow has no loop node.

gate approved writes no when approved: approved goes on to publish, and revise sends the draft back. when rejected ends the flow.

4 · Best practices

Each rule shows the flow to avoid beside the flow to write, each with its graph. Point at a line or a card: the other side shows its match.

Keep only what a reviewer would notice

A fact is a node only when its change would show in the result or in the dialogue. All else is prose or stays in the skill.

Add a node only where something changes

The executor, a question to the user, a branch, or data a reviewer would notice. Model actions in a row are one step.

Say the intent in one sentence

Two at most, 200 characters, or one list of up to five items. The details stay in the skill; ref= points to them.

Write a loop or a retry as prose

A flow has no loop node.

Pick the node by what the human does

An approval is a gate. An answer that changes the path is a decide by=human. Any other answer is an input of the node that asks.

Name data once

Write output or input where the data first appears, with a description. A later change and a later read are prose.

Make a rule an invariant only when it limits the whole flow

Say who keeps it with by=. A rule about the result is prose of the node that makes the result.

Write a shared failure once

A failure that several steps handle the same way is one invariant that names the script. A catch holds only the failures of its own step.

Mark what the skill does not say

Write // ? with the file and line above the node. Do not guess.

Run fmt, then validate, after each edit

fmt lays out the file and changes no word. Each validator message has its line and its fix.

node skillflow.mjs fmt flow.kdl
node skillflow.mjs validate flow.kdl

5 · Editor

skillflowctl edit <skill> opens the flow in the browser. The Source view in Edit mode holds the text, and the graph follows it.

  • Type. Suggest (Alt+↓ or Ctrl+Space) shows what fits at the cursor. The order of the nodes and the when blocks make the connections.
  • Problems. Each problem has its line and its fix; F8 goes to the next one. While the text has errors, the graph shows the last valid text.
  • Save vs export. Save flow (Ctrl+S or ⌘S) writes the flow file. Export review page in the header writes a page for review: the last valid flow and its comments, in one HTML file.
  • A change on disk. When another program changes the file while the text has unsaved edits, Save shows both versions and writes only the one you choose.
  • No connection. When the editor server does not answer, the text stays in the page and the editor connects again by itself. Until then, Save writes to a file that you pick, or downloads a copy. A download is not linked to the editor, so the text still counts as unsaved.
  • History. The bar keeps the edits of this visit until the tab closes. A new edit at an earlier point replaces the later ones; Undo brings the text back.
  • Fields. A suggestion can put in a template with fields, and a frame marks the field to fill. Tab goes to the next field and Shift+Tab to the one before; a template with one field ends on Tab or Shift+Tab, as on Enter. Enter ends a field on one line, such as a "…" string, and goes to the next field; after the last field, the cursor goes to the end of the line. In a field on a line of its own, Enter adds a line and Shift+Enter ends the field. Escape ends the fields.
  • Views. The tabs show the graph alone, the graph and the text side by side or one above the other, or the text alone.
  • Keys. Escape, then Tab, leaves the text field. Ctrl+Enter or ⌘Enter checks the text and draws the graph again.
